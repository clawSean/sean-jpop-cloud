Deployment

Archive first, verify second, swap last.

$ sean deploy-procedure
  1. archive current live root
  2. build and update source repo
  3. validate HTML, CSS, and links
  4. screenshot desktop + mobile
  5. copy to deploy root
  6. verify public HTTPS access

$ sean privacy-check
  public:   patterns, proof, architecture
  private:  contacts, secrets, credentials, raw memory

Startup architecture

Product shape hiding inside the setup.

Personal ops layer

One always-on assistant with chat, memory, browser work, and deployment access becomes a lightweight operating layer for a person or tiny team.

Receipts-first trust

The product story should prove itself through public work, commits, verified contributions, and repeatable workflows instead of abstract agent promises.

Modular surface area

Skills, plugins, cron, browser control, and channel UI can stay modular while the user experience feels like one coherent teammate.

Setup

How Sean's environment is configured.

Single VPS

OpenClaw agent, Telegram gateway, Caddy web server, headless browser, git repos, and deployed sites all run on the same Ubuntu box. This is Sean's current setup.

File-first state

Memory, knowledge, project progress, and operational state are stored as plain files in git repos. No database. Survives restarts cleanly.
